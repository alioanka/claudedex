Telegram Notifications Configuration
Topic-Routed Notifications: Each trading module posts to its own Telegram topic thread inside a single supergroup. Set up your bot and group first — see docs/TELEGRAM_SETUP.md for the step-by-step guide. Leave topic IDs blank to fall back to legacy single-DM mode.
Master Control
Master on/off switch. Disabling this suppresses all Telegram messages regardless of other settings.
Supergroup Identity
The supergroup chat ID (begins with -100). Obtain via curl https://api.telegram.org/bot<TOKEN>/getUpdates — look for message.chat.id after sending a message to the group.
Timing & Deduplication
How often to post the full-dashboard summary to the Dashboard topic. Default: 3 hours.
How often to post the cross-module P&L summary to the Summary topic. Default: 6 hours.
Identical error messages within this window are suppressed. Default: 900 s (15 min).
Topic Thread IDs

Each field maps to one forum topic inside your supergroup. Right-click a topic message in Telegram desktop and choose "Copy Link" — the trailing number is the thread ID. Or use getUpdates and read message.message_thread_id. Leave blank to skip that topic.

Module Topics
System Topics
Periodic dashboard snapshots (every 3 h).
Cross-module P&L summary (every 6 h).
All ERROR-level events from every module. De-duplicated per the window above.

Per-Module Verbosity

all — every trade signal, entry, and exit is posted. summary — only hourly/periodic summaries (recommended for high-frequency modules like Solana which can generate ~1 000 messages over 2-3 days). off — no messages for this module regardless of topic ID.

Solana defaults to summary — "all" can generate ~1 000 messages in 2-3 days on an active bot.
Verification
Send Test Message: Save your settings first, then use the Telegram Bot API directly to verify each topic receives a message: 
curl "https://api.telegram.org/bot<TOKEN>/sendMessage" \
  -d chat_id=<GROUP_ID> \
  -d message_thread_id=<TOPIC_ID> \
  -d text="ClaudeDex test message"
A "Send Test Message" button that calls the notification engine directly is tracked as a follow-up in MASTER_BACKLOG.md (requires engine agent coordination to avoid coupling).
Legacy Single-DM Mode

If telegram_group_id is blank or all topic thread IDs are blank, the notification engine falls back to the original behaviour: messages are sent to the single chat ID configured in Secure Credentials (TELEGRAM_CHAT_ID). No group or topic setup is needed for legacy mode.

The bot token is always read from TELEGRAM_BOT_TOKEN in the Secure Credentials vault (Settings → Secure Credentials). Never paste it here.
